Change the search or reset the filters.

Loading uses the existing Spinner row, and a failed request shows a red “Couldn't load channel inventory.” row, as on Adjustments.

Filters (existing components)

  • Search (FilterItem wide): SKU, product name, and ASIN or FNSKU for Amazon. Applied with the other filters, not as you type.
  • Channel (single select): Amazon, Walmart. Defaults to Amazon. Changing it resets Marketplace and Fulfillment in the draft.
  • Marketplace (FilterMultiSelect, empty = any): Amazon US, CA, MX · Walmart US, CA.
  • Fulfillment (FilterMultiSelect, empty = any): FBA · WFS, Seller fulfilled.
  • Reset / Apply filters from FilterBar. State comes from useStagedFilters; applying returns to page 1.

API (paginated, server-side filtering)

  • GET /inventory/channel-stock?channel=&marketplaces=&fulfillment=&search=&page=&limit=20
  • Returns { data, page, limit, totalRecords, totalPages, summary, syncedAt }, the same pagination format PaginationFooter uses elsewhere.
  • summary (SKUs, available, inbound, out of stock) covers every filtered row, not only the current page, so the cards match the table.
  • One reader per channel converts its own table (fba_inventory, walmart_inventory) into the same row format. Adding Shopify or Wayfair means adding one reader.
  • The dropdown options come from the same endpoint's metadata (GET /inventory/channel-stock/options), so the screen and the backend use the same option lists.

Table

  • The same columns for every channel. A dash means the channel doesn't report that figure.
  • Available shows in red when it's 0. Header stays fixed while the table scrolls, like Adjustments.
  • Route /dashboard/inventory/channel-inventory, added to the sidebar and route permissions next to Adjustments.

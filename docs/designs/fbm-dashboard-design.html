Beddora · Shipping › Orders · FBM dashboard3 / 4 · Interactions, states, responsive

Interactions

ElementBehaviour
KPI cardClick opens Orders with that state applied and the current channel / marketplace / date filters carried over. "To book" and "Needs attention" are outlined amber / red because they are the work queue.
Pipeline stageSame as a KPI; bar length is the share of the largest stage.
Needs attention rowInline action: Retry all (bulk "Retry mark shipped", write permission only), Map SKU (SKU mapper), Counts refresh after the action.
Top filtersChannel, marketplace and date range apply to every card on the tab, using the same staged "Filter" pattern as the list so cards don't flicker while picking.
Permissionsshipping:orders read shows the Overview; write actions are hidden without write.
ExportExisting "shipping-orders" Excel export, scoped to the active filters.

States

  • Loading: card skeletons.
  • Empty: "No orders in this range" with a "Last 90 days" shortcut (existing EmptyState).
  • Error: a card fails alone with "Could not load" and Retry; the rest stays.
  • Unconnected channel: greyed in the filter with "Not connected", as today.
  • Zero attention: the card becomes a green "All clear" line.

"Ship by" deadline / overdueMISSINGNo ship-by date on orders today, so it is left out. Add a 7th KPI "Overdue to ship" once the channel's promised date is stored.

Build plan (reusing what's there)

  • Backend: one GET /shipping/orders/overview taking the list's filters (channels, countries, from, to) and returning counts, daily series, spend by carrier and attention counts, so the cards load together and share filters.
  • API slice: useGetOrdersOverviewQuery in services/api/shipping.api.ts, beside useGetChannelOrdersQuery.
  • Feature: features/shipping/orders/overview/ with OverviewTab and small pure cards (PipelineCard, AttentionCard, SpendCard, OrdersPerDayCard) so one failing card doesn't block the rest.
  • Reuse: KpiCard, FilterBar + useStagedFilters, DateRangePicker, StatusBadge, ChannelBadge, EmptyState, design-system/charts, FULFILLMENT_META, STATUS_TONE.
  • Routing: tab in the address (?tab=overview|orders), like the booking drawer's ?shipment=. KPI clicks write ?tab=orders&states=…; OrdersScreen reads states as initial filter, as it already does for search.
  • Permissions: reuse shipping:orders; no new subject.

Decisions for you

  • Tabs (Overview | Orders) as drawn, or the KPI strip above the existing list on one page?
  • Overview as the default landing, or keep landing on the list?
  • Is on-time % needed in v1 (needs delivery-date data)?
  • Can we store a promised ship-by date from Amazon / Walmart for an "Overdue" KPI?

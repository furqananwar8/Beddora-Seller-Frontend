Findings from the run

Nothing broke. These are things noticed while walking the flow.

#FindingSuggested action
1The list shows “1 units” for a single damaged unit (step 11 and 14).Pluralise: “1 unit”. Small copy fix on the receiving list.
2The receiving form starts cartons from the scan, rounded to whole cartons. With 4 units of a 10-per-carton product that is 0 cartons, so everything shows as shortage until the scan reaches a full carton (step 12).Fine for real container volumes. If small partial counts matter, show the leftover units under the carton fields.
3The row menu has a third item, Download PDF, next to Update and Scan items (step 2). The v4 design page for Inbound Receiving lists only two.Add “Download PDF” to the design menu so it matches.
4The “over expected” case was not exercised: this dummy container expected 30 units of A and only 4 were scanned. That case was covered in the earlier service-level test.Re-run with a smaller expected quantity if you want it on screen.
5The scanned-units column on the receiving form is cut off on narrow windows (about 1200px) and needs a horizontal scroll (step 12).None needed for desktop widths. It is a display detail, not a data issue.
